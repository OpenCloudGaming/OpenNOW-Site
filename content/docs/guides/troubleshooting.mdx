Most OpenNOW problems fall into one of four layers: authentication, the GeForce NOW session, the local native stream path, or input. Start with the quick checks below, then use the section that matches what you see.

<Callout type="info" title="Check NVIDIA first">
OpenNOW depends on NVIDIA's login, catalog, CloudMatch, queue, and streaming services. If the official GeForce NOW client is also failing, wait for the service to recover before changing local settings.
</Callout>

## Five-minute check

<Steps>
  <Step>
    **Restart OpenNOW.** This clears the active session UI and forces the app to rebuild local process state.
  </Step>
  <Step>
    **Use conservative stream settings.** Choose H.264, 1920×1080, 60 FPS, and a lower bitrate. If that works, restore one setting at a time to find the unsupported codec, profile, or bandwidth threshold.
  </Step>
  <Step>
    **Leave video backend on Auto.** In Settings → Stream, keep the native video backend on **Auto** unless you are deliberately isolating a GPU/API problem.
  </Step>
  <Step>
    **Try another game and region.** One title can have a membership or storefront restriction, while one region can have queue or server-capacity trouble.
  </Step>
  <Step>
    **Capture diagnostics before resetting data.** Use **Settings → About → Copy diagnostics**, and note the exact message, game, provider, region, app version, and steps that reproduce the problem.
  </Step>
</Steps>

## Sign-in and account

<Accordions type="multiple">
  <Accordion title="The browser signs in but OpenNOW does not continue">
    Keep OpenNOW open while completing browser OAuth. The callback returns through a temporary local HTTP port, so a firewall, privacy tool, proxy, or another process can block it. Allow OpenNOW on the local network and retry. If the browser flow remains blocked, use **Sign in with QR** instead.
  </Accordion>
  <Accordion title="The QR code expires or authorization never completes">
    Start a new QR attempt and complete it before its timer expires. If NVIDIA responds with `slow_down`, leave the page open; OpenNOW adjusts its polling interval automatically. Make sure the phone and OpenNOW use the same intended NVIDIA or alliance-provider account.
  </Accordion>
  <Accordion title="OpenNOW asks you to sign in again">
    The saved access and refresh tokens may have expired or been rejected. Sign in again first. If every restart loses a valid session, close OpenNOW, back up auth/session files under the OpenNOW data directory, remove them, and retry so the app can create clean authentication state.
  </Accordion>
  <Accordion title="A game is missing after linking a store">
    Open **Settings → Accounts** (or Stores), link or resync the supported store, then refresh the library. OpenNOW invalidates account-scoped catalog caches after link, unlink, and resync actions, but NVIDIA still decides which owned games appear in GeForce NOW.
  </Accordion>
</Accordions>

## Launch, queue, and session

| Symptom | What it usually means | What to try |
| --- | --- | --- |
| Upgrade or insufficient playability message | NVIDIA reports that the selected game or stream profile requires a higher membership tier | Choose an entitled game/profile or change the GeForce NOW membership |
| Active session conflict | NVIDIA believes another stream is still active | Stop the other session, wait for cleanup, then launch again |
| Queue does not advance | The selected region is at capacity, the queue request expired, or service state changed | Leave and relaunch; if available, choose another region |
| Game opens from the public catalog but not the library | The required store account is not linked or synced | Link/resync the store under Settings, then refresh |
| Catalog browse hangs or fails only with a session proxy enabled | Catalog requests that go through a failing proxy can time out, then retry direct | Wait for the direct retry; disable the proxy if catalog never recovers |
| Community proxy toggle fails or takes a long time | Community provision can cold-start; OpenNOW allows a longer wait and retries transient failures | Keep Settings open until provision finishes |
| One game fails while others launch | The failure is likely title, storefront, SKU, or membership specific | Record the exact game and storefront before reporting it |

Do not repeatedly relaunch while an earlier CloudMatch session is still being released. Stop the session once, wait briefly, then make one clean attempt.

## Stream quality and video

Start with **H.264 · 1920×1080 · 60 FPS** and a bitrate your connection can sustain. H.265, AV1, 10-bit color, 4:4:4 chroma, high frame rates, and ultrawide profiles require compatible subscription profiles plus local GPU, driver, and display support.

| Symptom | Isolation step | Next action |
| --- | --- | --- |
| Black screen with audio | Switch to H.264 and 8-bit 4:2:0, then restart the stream | Update the GPU driver; leave native video backend on Auto unless diagnosing |
| Regular stutter or rising latency | Lower bitrate first, then FPS | Use wired Ethernet or stronger Wi-Fi; stop competing traffic and try a closer region |
| Blocky image but stable input | Increase bitrate gradually | Keep the highest value that remains stable rather than the maximum available value |
| Colors look wrong | Return color quality to 8-bit 4:2:0 and disable experimental combinations | Re-enable 10-bit or 4:4:4 separately to identify the unsupported mode |
| Entire app window is black vs only the video surface | Note which one you see before changing settings | Export diagnostics and include both `native-streamer.log` and `qt-native.log` |

<Callout type="warn" title="Change one variable at a time">
Changing codec, resolution, FPS, bitrate, backend, and region together makes the result impossible to interpret. Begin with the conservative profile, then restore one option per stream.
</Callout>

## Input, controller, and microphone

- **Mouse does not control the game:** click the stream to acquire pointer lock. Use the configured release shortcut (default `F8`) before interacting with OpenNOW again.
- **Keyboard mapping is wrong:** confirm the selected keyboard layout in Settings and reconnect the stream after changing it.
- **Controller is not detected:** connect it before launching, verify the operating system sees it, then restart OpenNOW. Close remapping software temporarily if it creates duplicate virtual controllers.
- **Console / couch mode is hard to leave:** use the console exit control, pointer interaction when `leaveConsoleOnPointer` is enabled, or Settings to change shell preferences. Console mode changes the browsing UI but does not change NVIDIA account state.
- **Clipboard paste does nothing:** enable clipboard paste in Settings → Controls, make sure keyboard input is active in the stream, and use the configured paste path rather than assuming the OS shortcut alone is enough.
- **Microphone is silent:** grant microphone permission to OpenNOW at the operating-system level, select the intended mode in Settings, and reconnect the stream so capture is negotiated again.

See [Input and Controls](/docs/reference/input) for shortcuts, pointer behavior, and microphone modes.

## Native stream path

The Qt desktop app has one streaming path: the in-process native NVST streamer. There is no “return to Web streamer” isolation step.

1. Keep **native video backend** on **Auto** unless isolating a specific API.
2. Restart the stream after changing codec, resolution, color quality, or backend.
3. On black-screen reports, distinguish an entirely black application window from a stream-only black video surface.
4. Export **Settings → About → Copy diagnostics**. The report includes bounded redacted logs such as `native-streamer.log` and `qt-native.log` from the diagnostics directory.
5. Include GPU, driver version, platform package name (`OpenNOW-Qt-…`), and whether the same account/game works in the official GeForce NOW client.

Use [Native Streamer](/docs/reference/native-streamer) for packaging, GPU presentation, and protocol details.

## Reset local state

Local settings and authentication are separate. Close OpenNOW before moving or deleting either.

<LocalDataLocationsTable />

- Move `settings.json` aside to reset preferences without deleting the saved sign-in.
- Move auth/session files aside to reset the account session without resetting stream preferences.
- Back up files before destructive troubleshooting if you need to inspect or restore them later.
- Screenshots and recordings live in their own media directories; resetting settings or authentication does not require deleting captures.

## Collect a useful report

On desktop, prefer **Settings → About → Copy diagnostics**. You can also attach a structured session quality summary from the post-stream report when `showSessionReport` is enabled. Session summaries are privacy-safe aggregates and deliberately omit credentials, session IDs, and account identifiers.

If you file outside the app, include the following in a [GitHub issue](https://github.com/OpenCloudGaming/OpenNOW/issues) or the [OpenNOW Discord](https://discord.gg/8EJYaJcNfD):

- OpenNOW version and whether it is a stable, nightly, or source build (`OpenNOW-Qt-…` package name when applicable)
- Operating system, architecture, GPU, and GPU-driver version
- Provider, GeForce NOW membership tier, selected region, and game/storefront when relevant
- Codec, resolution, FPS, bitrate, color quality, and native video backend preference
- Exact error text and a short, repeatable sequence of steps
- Whether the same account and game work in the official GeForce NOW client
- A diagnostics export, screenshot, or session summary with tokens, email addresses, device codes, and other personal data removed

<Callout type="danger" title="Do not post credentials">
Never attach session files, access tokens, refresh tokens, QR device codes, or unredacted account details to a public issue.
</Callout>

Switch-specific crashes, installation failures, and decoder problems belong in the [OpenNOW-Switch issue tracker](https://github.com/OpenCloudGaming/OpenNOW-Switch/issues). Include whether Homebrew Menu was opened in applet mode or full-memory application mode.
