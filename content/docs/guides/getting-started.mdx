OpenNOW is an open-source GeForce NOW client. The desktop app is the Qt Quick client in `opennow-qt/`, with a Rust core and an in-process native NVST streamer. Separate native and mobile builds are available for other platforms.

<Callout type="info" title="Desktop is Qt/native">
OpenNOW's desktop client replaces the retired Electron/`opennow-stable` app. The Qt app has no Chromium/WebRTC fallback. See the [announcement](https://x.com/Zortosdev/status/2093023076191440963) for a first look.
</Callout>

## Download a release

The published GitHub Latest release is **v1.0.1** with `OpenNOW-Qt-1.0.1-…` packages (published 2026-09-13). Look for packages starting with `OpenNOW-Qt-` in [GitHub Releases](https://github.com/OpenCloudGaming/OpenNOW/releases) or use the [download picker](/#downloads). Use nightlies or [`qt-ci` on `dev`](https://github.com/OpenCloudGaming/OpenNOW/actions/workflows/qt-ci.yml?query=branch%3Adev) when you need post-1.0.1 builds. **v1.0.0** remains a historical release. Historical tags such as v0.5.5 may still contain the retired Electron app.

| Platform | Qt package | How to run it |
| --- | --- | --- |
| Windows x64 / ARM64 | `.msi`, portable `.zip` | Install the MSI, or extract the entire ZIP and run `bin/OpenNOW.exe` |
| Linux x64 / ARM64 | `.AppImage` (recommended) | Make the file executable, then launch it |
| Linux x64 / ARM64 | `.deb` | **v1.0.1** and nightly DEBs bundle Qt, QML plugins, SDL3, and the media runtime under `/opt/opennow`. Older **v1.0.0** DEBs still expect distro Qt 6.8+ and SDL3 — prefer the AppImage for that historical release on stock Ubuntu 24.04 |
| Linux x86_64 | Flatpak (optional) | Build/install locally from `opennow-qt/packaging/flatpak` (app id `io.github.opencloudgaming.OpenNOW`) or the **Qt Flatpak build** workflow artifact. Not published on Flathub. Flatpak installs disable the in-app self-updater |
| macOS Apple Silicon, macOS 13+ | `.dmg`, `.zip` | Open the DMG and drag OpenNOW into Applications, or extract the ZIP. Intel Macs are not included |
| macOS (OpenNOW Mac) | [Release `.zip`](https://github.com/OpenCloudGaming/OpenNOW-Mac/releases) | Separate performance-focused macOS build maintained by Jayian1890 |
| Android | [Google Play](https://play.google.com/store/apps/details?id=com.opencloudgaming.opennow) | Stable Android release; separate from the Qt desktop app |
| Android beta | [Direct `.apk`](https://grid.printedwaste.com/download/3770b4c2c342a60242a18db9) | Sideload the beta only when testing pre-release Android builds |
| iOS | [TestFlight beta](https://testflight.apple.com/join/u1XPJKH2) | Install through Apple's TestFlight while the iOS build is in beta |
| Nintendo Switch | [`SwitchNOW.nro`](https://github.com/OpenCloudGaming/OpenNOW-Switch/releases/latest) | Native Horizon OS homebrew client for modded Switch systems; follow the [Switch installation guide](/docs/guides/nintendo-switch) |

**v1.0.1** ships Ed25519-signed update manifests for every package. Apple Silicon DMG/ZIP builds are Developer ID–signed, notarized, and stapled. Windows MSI/ZIP packages are not Authenticode-signed, so SmartScreen or an unknown-publisher warning may appear. If you are coming from **v1.0.0** (or another build without the pinned update key), install **v1.0.1** manually once to establish trust for future signed updates. Automatic checks and optional downloads still require confirmation before install/restart. Nightlies may still be unsigned/not notarized. Flatpak builds have no native auto-update path. `SHA256SUMS` detects corrupted downloads; it does not verify who published a package. For historical **v1.0.0** packages (unsigned, non-notarized macOS), use System Settings → Privacy & Security → Open Anyway when Gatekeeper blocks the app — do not disable Gatekeeper globally.

## First launch

1. Open OpenNOW.
2. Complete first-run onboarding when prompted, or replay it later from **Settings → About → Replay onboarding**.
3. Sign in through the browser-based NVIDIA OAuth flow, or use **Sign in with QR** to authorize from another device.
4. Browse your library or the public catalog. Use Settings to link/resync supported store accounts when GFN requires account connections for owned games.
5. Open Settings to choose bitrate, codec, region, language, console/desktop preferences, and other options. Resolution and FPS choices follow the profiles reported by your current GFN subscription. Persistent in-game settings default **on** (`enablePersistingInGameSettings`) so supported games keep graphics preferences across sessions.
6. Use the same app in desktop (keyboard/mouse) or console (controller-first) layout. Console mode is a shell preference, not a separate download.
7. Launch a game. When a title has multiple store variants, choose the platform (Steam, Xbox, Epic, and so on) before the session starts. Queue and server-selection screens appear when GFN requires them. After a session ends, OpenNOW can show a privacy-safe session quality summary when `showSessionReport` is enabled (default on).

On Windows, if H.265 is unavailable, Settings can point you at Microsoft's HEVC Video Extensions (try the free Store offer first). Choosing 10-bit color shows a one-time stuttering warning. Background-stream options under Audio can mute the stream when OpenNOW loses focus and optionally request taskbar/dock attention every five minutes.

Some GFN catalog entries require a specific membership tier. When NVIDIA reports `INSUFFICIENT_PLAYABILITY`, OpenNOW shows a membership-upgrade launch error instead of treating it as a duplicate-session conflict.

Desktop streaming uses the in-process native NVST streamer. There is no web/Chromium streamer to fall back to. Export a diagnostic report through **Settings → About → Copy diagnostics** when something breaks. Report issues on [GitHub Issues](https://github.com/OpenCloudGaming/OpenNOW/issues) or [Discord](https://discord.gg/8EJYaJcNfD).

## Build from source

Use `main` for the release source or `dev` for ongoing development. Before building, install:

- Qt 6.8+ with Quick, Multimedia, and ShaderTools
- CMake 3.24+ and a C++20 toolchain
- SDL3, Cargo, and the media dependencies for your platform

Linux also needs `pkg-config`, `libwayland-dev`, and `wayland-protocols`, even for X11 builds. You do not need Node.js or npm to build or run the desktop app.

```bash
git clone --branch main https://github.com/OpenCloudGaming/OpenNOW.git
cd OpenNOW
cmake -S opennow-qt -B build/opennow-qt -DCMAKE_BUILD_TYPE=Debug
cmake --build build/opennow-qt
ctest --test-dir build/opennow-qt --output-on-failure
```

See the [Qt app guide](https://github.com/OpenCloudGaming/OpenNOW/blob/main/opennow-qt/README.md) for platform-specific details, hardware notes, and acceptance checks.
