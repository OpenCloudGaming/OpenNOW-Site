The native streamer is the **production** desktop streaming path. The Qt app loads `opennow-streamer-ffi` as an in-process shared library. It owns NVST transport, decode, audio, gameplay input, source-stream Matroska recording, and GPU frame publication. It does not implement the browser WebRTC offer/answer or trickle-ICE protocol, and the Qt app has no Chromium/WebRTC fallback.

<Callout type="info" title="No Electron child process">
Older docs described an experimental Electron-supervised Rust child process with a GStreamer `webrtcbin` backend and web fallback. That path is retired with Electron. Packaged Qt builds embed the streamer library beside the executable and `opennow-core`.
</Callout>

## How Qt uses it

1. Qt supplies one complete CloudMatch session context to the embedded engine.
2. The runtime reserves its sockets and performs the NVST session lifecycle (OPTIONS, DESCRIBE, SETUP, ANNOUNCE, PLAY, keepalive, TEARDOWN).
3. Qt lends current QRhi native graphics objects to the runtime.
4. Platform decode publishes a native GPU frame into a one-frame mailbox.
5. Qt imports the converted texture into the scene graph so QML overlays compose above video in the same window.

There is no separate streamer window, helper application, or packaged standalone streamer binary in Qt releases. The standalone `opennow-streamer` host remains a development tool only.

## Settings that matter

| Setting | Default | Purpose |
| --- | --- | --- |
| `streamClientMode` | `"native"` | Desktop streaming mode; Qt production path is native |
| `transportMode` | `"nvst"` | Native media transport |
| `nativeVideoBackend` | `"auto"` | Platform video/API preference; unsupported forced backends fail explicitly |
| `audioOutputDevice` | `""` | Opaque output device ID from native enumeration; empty means system default |
| `showNativeStreamerStats` | `false` | Native stats overlay preference |
| `enableCloudGsync` | `false` | Cloud G-Sync/VRR preference |
| `codec` / `fallbackCodec` | `"auto"` | Capability-aware codec preference before CloudMatch allocation |
| `colorQuality` | `"8bit_420"` | Bit-depth/chroma preference |

On Windows, the embedded presenter currently uses D3D11; explicit DX12/Vulkan interop for the embedded path may be unavailable even when standalone experiments exist. Leave **Auto** selected unless isolating a known GPU issue.

## Packaging

The Qt CMake build always compiles `opennow-streamer-ffi` with Cargo's release profile and links it into `opennow-qt`. CPack installs that library beside the Qt executable and `opennow-core`.

Look for assets named `OpenNOW-Qt-…` in [GitHub Releases](https://github.com/OpenCloudGaming/OpenNOW/releases). Linux packages can use a bundled FFmpeg fallback while optional GPU driver interfaces remain dynamically discovered.

## Local JSON protocol

The embedded engine speaks a versioned local JSON protocol (currently protocol 6) through the FFI command/response/event callbacks. Important user-facing capabilities include:

- session start/stop and telemetry
- microphone enable/toggle/state
- audio device enumeration
- clipboard text submission
- controller rumble events

See the upstream [streamer README](https://github.com/OpenCloudGaming/OpenNOW/blob/main/native/opennow-streamer/README.md) and [FFI README](https://github.com/OpenCloudGaming/OpenNOW/blob/main/native/opennow-streamer/crates/opennow-streamer-ffi/README.md) for command fields and ABI rules.

## Diagnostics

**Settings → About → Copy diagnostics** exports a bounded redacted report. On Windows the diagnostics directory is under `%APPDATA%/OpenNOW/diagnostics` (or `OPENNOW_DATA_DIR/diagnostics`). The export can include both `native-streamer.log` and `qt-native.log`.

When reporting black screens, say whether the entire application window is black or only the video surface is black. Include GPU, driver, package name, and the diagnostics export.
