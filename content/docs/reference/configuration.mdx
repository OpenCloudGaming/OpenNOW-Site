OpenNOW stores user settings as JSON in `settings.json` in the OpenNOW data directory. The Rust core owns load, migration, normalization, and save. The Qt Settings pages edit those values over the shell/core protocol.

The core repairs values on every load and write. A choice that is not in the allowed list returns to its default. A number outside its range is clamped. A value of the wrong JSON type returns to its default. Each save first copies the previous valid file to `settings.json.bak`. If `settings.json` cannot be parsed, the core loads the backup and renames the broken file to `settings.json.corrupt`. Keys the Qt app does not know are kept in the file but are not exposed to the UI.

**Settings → About & support → Reset all settings** restores every default. It keeps the onboarding state.

<Callout type="info" title="Qt defaults differ from Electron">
Desktop streaming defaults to native NVST (`streamClientMode: "native"`, `transportMode: "nvst"`). There is no web streamer setting to return to in the Qt app.
</Callout>

<Callout type="warn" title="Known issues in v1.0.2">
Prefer a **4:2:0** color profile. YUV **4:4:4** choices are labeled **Coming soon** because they are not working correctly. Alliance Partner sign-in remains available, but Alliance Partners may not work correctly. Keep NVIDIA as the fallback when an Alliance stream fails.
</Callout>

## File locations

<LocalDataLocationsTable pathHeader="Path" />

Set `OPENNOW_DATA_DIR` to use a different data directory. On Linux, if `~/.config/OpenNOW` does not exist but an older `~/.config/opennow` directory does, the core keeps using the older directory. The Flatpak build keeps its data inside the sandbox, under `~/.var/app/io.github.opencloudgaming.OpenNOW/`.

Diagnostics live under `diagnostics/` in the data directory. The core writes `current.log` and keeps the previous run in `previous.log` (5 MiB limit per file). The Qt app writes `qt-native.log` and the embedded streamer writes `native-streamer.log`.

## Video and stream

## Capture and recording

| Setting | Type | Default | Description |
| --- | --- | --- | --- |
| `replayBufferEnabled` | `boolean` | `false` | Keeps recent source video and audio in memory so you can save a clip. Enabling takes effect next session; disabling clears the buffer immediately. **Settings → Recording → Enable replay buffer** |
| `replayBufferSeconds` | `number` | `30` | Target clip length, 15–120 seconds. Memory limits and keyframe spacing can shorten a clip. **Settings → Recording → Replay duration** |
| `replayBufferMemoryMiB` | `number` | `256` | Memory limit for buffered media, 64–512 MiB. Higher bitrates fill it sooner. **Settings → Recording → Replay memory limit** |

Recordings and clips copy the incoming stream without re-encoding, so they use the stream's resolution, frame rate, and bitrate. The keys `recordingResolution` (`"720p"`), `recordingFps` (`30`), and `recordingBitrateMbps` (`null`) still exist in `settings.json`, but v1.0.2 does not read them. Recordings are Matroska (`.mkv`) files under the OpenNOW Pictures folder. See [Media](/docs/reference/media/).

## Input and shortcuts

Stream shortcuts are edited in **Settings → Controls → Shortcuts**. The page has search, reset to default, and clear. A cleared shortcut sends its key to the game. `Ctrl+G` and `Shift+F3` are reserved and cannot be assigned, and one chord cannot belong to two commands. See [Input](/docs/reference/input/) for the fixed shortcuts.

### Stored but unused in v1.0.2

These keys exist in `settings.json` and are normalized, but no v1.0.2 Settings page or stream path reads them: `aspectRatio` (`"16:9"`), `recordingResolution`, `recordingFps`, `recordingBitrateMbps`, `allowEscapeToExitFullscreen` (`false`), `hideStreamButtons` (`false`), and `hideServerSelector` (`false`). `mouseAcceleration` (`1`, range 1–150) and `nativeCursorOverlay` (`true`, **Settings → Controls → Advanced → Cursor overlay**) are read only by the external renderer process. The embedded stream view that the packaged app uses does not read them.

`consoleProfilePickerOnLaunch` (default `true`) is a v1.0.2 setting. **Settings → Console mode → Controller profile picker** ("Choose a saved profile when console mode starts") stores it, and nothing reads it. From v1.0.3-nightly.1046.1 it is no longer a setting. If `startAsLastUsedAccount` is missing and the saved value is `false`, load sets `startAsLastUsedAccount` to `true`. The old key stays in the file and is not shown.

## Diagnostics

Use **Settings → About & support → Export** to write a redacted diagnostic report. The report is saved as `opennow-diagnostics-<timestamp>.txt` under `diagnostics/` in the data directory. It contains the previous and current core logs and bounded tails of `native-streamer.log` and `qt-native.log`. Secrets, URLs, tokens, e-mail addresses, and local user paths are redacted. Do not post credentials, tokens, or unredacted account details to public issues.
